Project 02: Advanced Customer Intent Classification

Project Overview

This project explores the classification of customer-support messages based on their underlying intent, urgency and complexity.

The objective is to demonstrate how customer messages can be transformed into structured, meaningful labels for AI training and evaluation.

Project Type: Independent Portfolio Simulation
Dataset: Synthetic customer-support messages

Project Objectives

* Identify the primary intent behind customer messages.
* Distinguish between similar or overlapping intents.
* Identify multiple requests within a single message.
* Assign appropriate urgency levels.
* Recognise ambiguous customer requests.
* Maintain consistent annotation standards.

Intent Categories

Label	Description
REFUND	Customer requests reimbursement.
ORDER_TRACKING	Customer asks about order or delivery status.
CANCELLATION	Customer wants to cancel an order or service.
ACCOUNT_ACCESS	Customer reports login or account access problems.
BILLING	Customer reports payment or billing issues.
TECHNICAL_SUPPORT	Customer reports a technical problem.
COMPLAINT	Customer expresses dissatisfaction or reports poor service.
INFORMATION_REQUEST	Customer requests general information.
ACCOUNT_UPDATE	Customer requests changes to account information.
REPLACEMENT	Customer requests a replacement product.

Urgency Classification

Level	Description
Critical	Immediate action is required due to a serious issue or significant risk.
High	The issue significantly affects the customer’s ability to use a service or complete an important transaction.
Medium	The customer needs assistance, but the issue is not immediately disruptive.
Low	General questions or non-urgent requests.

Annotation Methodology

Each message will be evaluated using the following dimensions:

1. Primary intent.
2. Secondary intent, where applicable.
3. Urgency level.
4. Sentiment.
5. Annotation rationale.
6. Confidence level.

Complex Cases

Special attention will be given to:

* Messages containing multiple requests.
* Complaints that also include refund requests.
* Billing issues involving duplicate transactions.
* Technical problems that prevent account access.
* Messages where urgency is implied rather than explicitly stated.

Quality Assurance

Annotations will be checked for:

* Correct identification of customer intent.
* Consistent use of category definitions.
* Appropriate urgency assignments.
* Accurate handling of multiple intents.
* Clear annotation rationales.

Expected Deliverables

* Structured customer intent dataset.
* Multi-dimensional annotation labels.
* Intent classification guidelines.
* Ambiguity and error analysis.
* Quality assurance report.
