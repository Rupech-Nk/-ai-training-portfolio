Speech-to-Text Annotation Guidelines

1. Purpose

These guidelines establish a consistent process for evaluating AI-generated transcripts against reference transcripts.

The goal is to identify transcription errors, preserve the speaker’s intended meaning, and document corrections accurately.

2. Annotation Categories

Each transcript should be reviewed using the following error categories.

Error Type	Definition	Example
Word Omission	A spoken word is missing from the transcript.	“I haven’t received it” becomes “I have received it.”
Word Substitution	A word is replaced with an incorrect word.	“Billing” becomes “building.”
Word Insertion	A word appears in the transcript but was not spoken.	An extra word is introduced.
Number Substitution	A spoken number is transcribed incorrectly.	“Fifteen” becomes “Fifty.”
Number Omission	A digit or number is missing.	An order number loses one digit.
Proper Noun Error	A name or place is incorrectly recognised or spelled.	“Douala” becomes “Duala.”
Negation Error	A negative expression is omitted or incorrectly transcribed.	“I haven’t received it” becomes “I have received it.”
Punctuation Error	Punctuation is missing or incorrectly placed.	Two separate sentences are joined incorrectly.
No Error	The transcript accurately represents the reference.	Both versions match.

3. Evaluation Procedure

For every example:

1. Read the reference transcript carefully.
2. Compare it with the AI-generated transcript.
3. Identify missing, inserted, substituted or incorrectly recognised words.
4. Check numbers, names, dates, times and other important details.
5. Assess whether the error changes or obscures the original meaning.
6. Produce a corrected transcript.
7. Document the reason for the correction.

4. Correction Principles

* Preserve the speaker’s original meaning.
* Do not invent information that is absent from the reference.
* Pay particular attention to negations because they can reverse meaning.
* Verify numbers, dates, times and identifiers carefully.
* Preserve proper names as they appear in the reference.
* Avoid unnecessary rewriting or grammatical improvements.
* Do not treat every punctuation or formatting difference as a word-recognition error.

5. Special Cases

Contractions

Contractions and their expanded forms may communicate the same meaning. Record wording differences separately from meaning-changing errors.

Numbers and Identifiers

Numbers in order references, dates and contact details require special attention because even one incorrect digit can cause practical problems.

Proper Names

Names of people, businesses and locations should be checked carefully. Similar-sounding words can produce incorrect entities.

Spoken Email Addresses

Spoken email addresses may require normalisation into written form. The annotation should preserve the exact characters supported by the reference rather than guessing missing information.

6. Quality Assurance

Before finalising an annotation, verify that:

* The error category matches the actual difference.
* The corrected transcript follows the reference.
* Important details have not been changed.
* The evaluation note explains the error clearly.
* The annotation does not introduce unsupported information.

7. Limitations

This project uses simulated transcripts and reference text. No actual audio recordings or commercial speech recognition outputs were used.

The examples demonstrate transcription evaluation and correction skills, not measured performance of a speech recognition model.
